# ViewTube Studio Design Plugin

A repository-grounded design and engineering command system for ViewTube Studio, covering source authority, primitive intelligence, token lineage, visual analysis, component adoption, UX/accessibility, regression intelligence, health reviews, supervised implementation, verification, and user-controlled task instructions.

## Six sections

1. **Design Intelligence** — authority, provenance, ownership, dependencies, contract drift, token lineage.
2. **Component Intelligence** — primitives, APIs, composition, reuse, compatibility, adoption and migration.
3. **Creative Design** — visual references, anatomy, geometry and responsive composition.
4. **UX Intelligence** — journeys, usability, accessibility and interaction states.
5. **Quality Assurance** — unified audits, state coverage, regression, visual diff and browser verification.
6. **Implementation** — approved changes, tests, exports, documentation and repository handoff.

## Specialist capabilities

- Canonical steward and Command Center: `viewtube-studio-design`, `viewtube-design-command-center`.
- Architecture and primitives: `viewtube-architecture-steward`, `viewtube-primitive-engine`, `viewtube-component-relationship-explorer`, `viewtube-component-adoption-migration-planner`.
- Visual intelligence: `viewtube-visual-reverse-engineering`, `viewtube-visual-intelligence-engine`, `viewtube-visual-diff-triage`, `viewtube-browser-pixel-verification`.
- Tokens and contracts: `viewtube-design-token-inspector`, `viewtube-contract-enforcement`.
- UX and QA: `viewtube-ux-accessibility`, `viewtube-interaction-state-matrix-builder`, `viewtube-unified-design-audit`, `viewtube-regression-intelligence`, `viewtube-correction-intelligence`, `viewtube-design-system-health-review`.
- Implementation: `viewtube-design-to-code`.
- Instruction governance: `viewtube-agent-instruction-controls`.

## Agent instruction controls

Use `viewtube-agent-instruction-controls` to inspect plugin-authored rules, see their source and owning agent, and enable/disable configurable instructions for a specific task. The checklist distinguishes `LOCKED`, `REQUIRED`, `CONFIGURABLE`, and `OPTIONAL` rules. Task overrides are scoped to that task; they do not alter global defaults or other tasks. Host/platform policies, hidden instructions, tool permissions, and required safeguards are not exposed or toggleable. Task-scoped controls are conversational unless an actual persistence mechanism is available and authorized.

## Governance

The repository's current `docs/registry.json` and normative docs remain authoritative. This is a skills/workflow package, not an autonomous runtime, shadow registry, token store, test database, or background monitor. It does not grant repository, browser, persistence, deployment, or Git permissions. Report only evidence actually observed.
